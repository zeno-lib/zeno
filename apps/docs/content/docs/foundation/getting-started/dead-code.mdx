[fallow](https://fallow.tools) reads the import graph of the whole repo. It reports unused files, exports and dependencies, import cycles, duplicated code and complex functions. Biome checks one file at a time, so it can't tell that no other file imports an export.

`@zeno-lib/fallow` is the fallow preset for a Next.js, Supabase and Drizzle monorepo. It plays the same role for fallow that [`@zeno-lib/typescript`](/docs/foundation/getting-started/typescript) plays for `tsconfig.json`.

## Installation

Install fallow and the preset at the root of the monorepo:

```bash
pnpm add -D -w fallow @zeno-lib/fallow
```

The preset needs fallow 3.43.1 or later. Its `minimumVersion` stops an older fallow with a message that names both versions.

## Configuration

Create `.fallowrc.jsonc` at the root and extend the preset:

```jsonc title=".fallowrc.jsonc"
{
  "$schema": "./node_modules/fallow/schema.json",
  "extends": "npm:@zeno-lib/fallow",
  // Every package in the repo is private, so an export that no workspace imports is dead code.
  "includeEntryExports": true,
  // fallow reads the preset through `extends`, and no code imports it.
  "ignoreDependencies": ["@zeno-lib/fallow"]
}
```

`includeEntryExports` makes fallow check the exports of entry files too, such as a package's `index.ts`. Leave it out if the repo publishes packages, or list those in `publicPackages`.

## Commands

```bash
# Unused code, duplication and complexity, across the repo
pnpm exec fallow

# Only the findings that the current branch adds
pnpm exec fallow audit --base origin/main

# The plugins fallow runs, the preset's included
pnpm exec fallow list --plugins
```

## What the preset sets

### Credits

fallow already knows the files that Next.js, Drizzle, Playwright, PostCSS and Vitest read, and the exports of Next.js routes and metadata images. The preset credits what fallow misses:

| File or package | What uses it |
|---|---|
| The `default` export of `i18n/request.ts` | next-intl's plugin |
| `image-loader.ts` and its `default` export, in a package that depends on `@zeno-lib/supabase` | Next.js `images.loaderFile`, as in the [Storage image loader](/docs/core-framework/data-management/supabase#nextjs-storage-image-loader) |
| `*.test-d.ts` and `*.spec-d.ts`, as tests | Vitest's typecheck, which the [`@zeno-lib/test` presets](/docs/core-framework/testing/unit-testing) turn on |
| The `postcss-load-config` package | The JSDoc type at the top of the PostCSS config that `create-next-app` writes |

### Rules

The preset raises these rules to `error`, so they fail the run:

| Rules | Why |
|---|---|
| `misplaced-directive`, `invalid-client-export`, `mixed-client-server-barrel` | Next.js ignores a directive below an import, and rejects a server-only export from a `"use client"` file. A barrel with both pulls server code into the client bundle. |
| `security-client-server-leak` | A `"use client"` file must never reach a server secret. `fallow security` reports it. |
| `unused-server-actions`, `unused-component-props` | A server action that nothing calls, or a prop that its component never reads, is dead code. |
| `package-cycle`, `re-export-cycle` | Workspace packages and barrels never import each other in a loop. |
| `unused-dev-dependencies`, `type-only-dependencies`, `test-only-dependencies`, `dev-dependencies-in-production`, `unused-dependency-overrides` | Each package lists the dependencies it uses, in the right field. |
| `stale-suppressions`, `require-suppression-reason` | A `fallow-ignore` comment gives its reason after `--`, and goes once its finding does. |
| `test-only-branch` | `fallow audit` fails on production code that branches on running under a test. |

### Health

The preset sets `health.maxCrap` to `0`, which turns off CRAP findings. CRAP mixes complexity with test coverage. Without a coverage report, fallow guesses coverage from the files that Vitest tests import. Playwright tests import no source file, so fallow would fail every component with 5 branches.

Once CI writes a coverage report, point `health.coverage` at it and set `health.maxCrap` back to fallow's default of 30.

## Your own settings

fallow's `extends` merges objects key by key. An array in your config replaces the preset's array instead of adding to it. The preset sets no array that you write, so these settings stay yours:

- `entry`, `ignorePatterns`, `ignoreExports`, `ignoreDependencies`, `ignoreFindings` and `overrides`
- `duplicates.ignore`, `health.ignore` and `boundaries`

To change one rule or threshold, set that key alone. The other keys of `rules` and `health` keep the preset's values.

<Callout type="warn">
Never set `framework`. The preset's credits are plugins in `framework`, and your array would replace them without a warning. Write your own plugin in `.fallow/plugins/<name>.jsonc` instead. fallow loads it next to the preset's, and `fallow list --plugins` shows both.
</Callout>

### Exemptions to add

A few findings depend on names that only your repo knows:

- An app that the e2e package lists in `devDependencies`, so that Turbo builds it before the tests, is never imported. Add each app to `ignoreDependencies`.
- The output of `supabase gen types` is generated. Add it to `ignoreFindings` and `duplicates.ignore`.
- A script that only a CI workflow or a person runs has no importer. Add it to `entry`.
