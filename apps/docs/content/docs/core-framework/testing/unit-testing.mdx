Zeno uses [Vitest](https://vitest.dev) for fast, modern unit testing with native TypeScript support. The `@zeno-lib/test` package wraps Vitest with shared, opinionated configs so every package tests the same way — you don't install or configure Vitest yourself.

## What you get

Adding `@zeno-lib/test` gives you a single dependency that provides everything needed to write and run tests:

| Import | What it provides |
|---|---|
| `@zeno-lib/test` | Re-exports all of Vitest's runtime (`describe`, `test`, `expect`, `vi`, `beforeEach`, …) |
| `@zeno-lib/test/configs` | The `defaultConfig` and `reactConfig` presets, plus `defineConfig` / `mergeConfig` |
| `@zeno-lib/test/testing-library` | Re-exports [`@testing-library/react`](https://testing-library.com/docs/react-testing-library/intro) (`render`, `screen`, …) |
| `@zeno-lib/test/user-event` | Re-exports [`@testing-library/user-event`](https://testing-library.com/docs/user-event/intro) for simulating real user interactions |

The `vitest` CLI binary is also shipped by the package, so there's no need to add `vitest` to your own `devDependencies`.

## Installation

In the package you want to test, follow these steps.

### 1. Install the package

Install `@zeno-lib/test` as a dev dependency:

```npm
npm install --save-dev @zeno-lib/test
```

### 2. Add the test scripts

The `vitest` CLI is provided by the package, so you can wire up scripts directly:

```json title="package.json"
{
  "scripts": {
    "test": "vitest --run",
    "test:watch": "vitest watch"
  }
}
```

### 3. Create a Vitest config

Create a `vitest.config.ts` at the root of your package and re-export **one** config — pick the preset that matches your package (see [Choosing a config](#choosing-a-config) for the differences).

For plain TypeScript packages, use `defaultConfig`:

```typescript title="vitest.config.ts"
export { defaultConfig as default } from "@zeno-lib/test/configs"
```

For React packages, use `reactConfig` instead so component tests run in a DOM environment:

```typescript title="vitest.config.ts"
export { reactConfig as default } from "@zeno-lib/test/configs"
```

### 4. Write your first test

Create a `*.test.ts` file (or `*.test.tsx` for React) under `src/`, `test/`, or `tests/`:

```typescript title="src/example.test.ts"
import { describe, expect, test } from "@zeno-lib/test"

describe("Example", () => {
  test("works", () => {
    expect(true).toBe(true)
  })
})
```

### 5. Run it

```bash
pnpm test
```

## Choosing a config

The package ships two presets. Pick the one that matches your package.

### `defaultConfig`

For plain TypeScript packages (no DOM). It:

- Resolves your `tsconfig` path aliases (`vite-tsconfig-paths`).
- Loads environment variables from `.env.test` automatically.
- Discovers tests matching `{src,test,tests}/**/*.test.ts`.
- Enables [type testing](#type-testing) for `{src,test,tests}/**/*.test-d.ts` files.

### `reactConfig`

Extends `defaultConfig` with what React component tests need:

- Runs tests in a `jsdom` environment so the DOM is available.
- Enables the React plugin with the automatic JSX runtime — no `import React` needed.
- Widens test discovery to `{src,test,tests}/**/*.test.{ts,tsx}` so `.tsx` tests are included.

<Callout type="info">
Both configs set `globals: false`. This means Vitest helpers are **not** injected into the global scope — you must import `describe`, `test`, `expect`, etc. from `@zeno-lib/test` in every test file. This keeps test files explicit and type-safe.
</Callout>

### Extending the config

To override shared defaults, merge a preset with package-specific options:

```typescript title="vitest.config.ts"
import { defineConfig, mergeConfig, reactConfig } from "@zeno-lib/test/configs"

export default mergeConfig(
  reactConfig,
  defineConfig({
    test: {
      // package-specific overrides
    },
  }),
)
```

## Writing tests

Import the helpers you need from `@zeno-lib/test` (remember: there are no globals):

```typescript
import { describe, expect, test } from "@zeno-lib/test"

describe("Calculator", () => {
  test("adds two numbers", () => {
    expect(1 + 2).toBe(3)
  })

  test("handles edge cases", () => {
    expect(0 + 0).toBe(0)
    expect(-1 + 1).toBe(0)
  })
})
```

### File location and naming

Tests live alongside your source in `src/` and must end in `.test.ts` or `.test.tsx` to be picked up:

```
src/
├── calculator.ts
├── calculator.test.ts      # unit test
├── button.tsx
└── button.test.tsx         # React component test
```

## Testing React components

Use `@zeno-lib/test/testing-library` for rendering and querying, and `@zeno-lib/test/user-event` to simulate interactions. Both require the `reactConfig` preset.

`@zeno-lib/test/testing-library` is [React Testing Library](https://testing-library.com/docs/react-testing-library/intro) and `@zeno-lib/test/user-event` is [User Event](https://testing-library.com/docs/user-event/intro), re-exported without changes. Refer to their official documentation for the complete API.

These libraries let you test components the way a user actually experiences them, rather than reaching into implementation details:

- **React Testing Library** mounts a component into the `jsdom` DOM and exposes queries (`getByRole`, `getByText`, …) that find elements by their accessible role and visible text. Asserting on what's on screen — instead of on internal state or props — keeps tests resilient to refactors.
- **User Event** dispatches realistic interaction sequences (a click fires `pointerdown`, `mousedown`, `focus`, `click`, …), so tests exercise the same event flow a real user triggers, catching bugs that a single synthetic event would miss.

```tsx
import { describe, expect, test, vi } from "@zeno-lib/test"
import { render, screen } from "@zeno-lib/test/testing-library"
import userEvent from "@zeno-lib/test/user-event"
import { Button } from "@zeno-lib/ui/button"

describe("Button", () => {
  test("renders with text", () => {
    render(<Button>Click me</Button>)
    expect(screen.getByRole("button")).toHaveTextContent("Click me")
  })

  test("calls onClick when pressed", async () => {
    const user = userEvent.setup()
    const onClick = vi.fn()

    render(<Button onClick={onClick}>Click me</Button>)
    await user.click(screen.getByRole("button"))

    expect(onClick).toHaveBeenCalledOnce()
  })
})
```

## Mocking

Vitest's [`vi`](https://vitest.dev/api/vi) helper is re-exported from `@zeno-lib/test`. See the [Mocking guide](https://vitest.dev/guide/mocking) for the full range of techniques (functions, modules, timers, globals, …):

```typescript
import { describe, expect, test, vi } from "@zeno-lib/test"

const mockFetch = vi.fn()

describe("API", () => {
  test("fetches data", async () => {
    mockFetch.mockResolvedValue({ data: "test" })
    const result = await mockFetch()
    expect(result.data).toBe("test")
  })
})
```

## Type testing

Both presets also type-check files ending in `.test-d.ts`. Use [`expectTypeOf`](https://vitest.dev/api/expect-typeof) to assert on types without running any runtime code. See Vitest's [Testing Types guide](https://vitest.dev/guide/testing-types) for the full API:

```typescript title="src/types.test-d.ts"
import { expectTypeOf, test } from "@zeno-lib/test"

test("greet returns a string", () => {
  expectTypeOf(greet("world")).toBeString()
})
```

## Environment variables

Tests run with `NODE_ENV=test`. Both configs load `.env.test` automatically — create a `.env.test` file in your package for test-specific variables, and they'll be available via `process.env` during the run.

## Commands

```bash
# Run tests once
pnpm test

# Watch mode
pnpm test:watch

# Run a single test file
pnpm test src/example.test.ts
```

In a monorepo, scope the run to one package with Turborepo's `--filter`:

```bash
pnpm turbo run test --filter <package-name>
```
