Unlike unit tests, end-to-end tests don't live inside each app. They run with [Playwright](https://playwright.dev) from a single `packages/e2e` workspace that tests every app in your monorepo. `@zeno-lib/e2e` provides a shared config preset and testing utilities.

## How it fits together

Install `@zeno-lib/e2e` alongside its `@playwright/test` peer dependency, then download the browser binaries:

```npm
npm install --save-dev @zeno-lib/e2e @playwright/test
```

```bash
npx playwright install --with-deps
```

## Config preset

`@zeno-lib/e2e/config` exports `baseConfig`, a plain Playwright config object with the shared defaults. Spread it into `defineConfig` and add the app-specific `testDir` and `webServer`, which it deliberately omits:

```typescript title="playwright.config.ts"
import { defineConfig } from "@playwright/test"
import { baseConfig } from "@zeno-lib/e2e/config"

export default defineConfig({
  ...baseConfig,
  testDir: "./tests",
  webServer: {
    command: "npm run start -- -p 3000",
    url: "http://localhost:3000",
  },
})
```

`baseConfig` sets:

| Field | Locally | In CI |
|---|---|---|
| `projects` | one `chromium` project (`Desktop Chrome`) | same |
| `fullyParallel` | `true` | `true` |
| `forbidOnly` | off | **on**: a stray `test.only` fails the build |
| `retries` | `0` | `3` |
| `timeout` | 120s | 30s |
| `reporter` | `list` | `html` |
| `use.trace` | `on-first-retry` | `on-first-retry` |

## Dependency verifier

In a monorepo, e2e tests should run against freshly built apps. `@zeno-lib/e2e/verify-deps` checks that every app with a matching test folder is listed as a dependency of the e2e package, so that a task runner like Turborepo rebuilds it (via `^build`) before the tests run.

Run the `zeno-verify-app-deps` CLI before your e2e task. If a tested app is missing from the package's dependencies, it exits and prints the required dependencies.

```bash
zeno-verify-app-deps --apps-dir ../../apps --tests-dir ./tests
```

| Flag | Option | Default | What it does |
|---|---|---|---|
| `--apps-dir` | `appsDir` | `../../apps` | Directory that contains the apps |
| `--tests-dir` | `testsDir` | `./tests` | Directory with one folder per tested app |
| `--package-json` | `packageJsonPath` | `./package.json` | package.json whose deps must list the apps |

The same check is available as `verifyAppDeps(options)`, which returns `{ ok, checked, missing }` instead of exiting:

```typescript title="scripts/check-e2e-deps.ts"
import { verifyAppDeps } from "@zeno-lib/e2e/verify-deps"

const { ok, missing } = verifyAppDeps({
  appsDir: "../../apps",
  testsDir: "./tests",
  packageJsonPath: "./package.json",
})
```

## Common mistakes

- **Skipping `npx playwright install`.** The npm install brings the test runner but not the browsers, so every run fails at launch with "Executable doesn't exist".
- **Treating a local pass as a CI pass.** In CI `baseConfig` turns on `forbidOnly` (a leftover `test.only` fails the build) and drops the timeout from 120s to 30s, so a slow test can pass locally and time out in CI.
- **Not listing a tested app in the e2e package's deps.** The task runner has no edge to rebuild it, so tests run against a stale build. The verifier catches exactly this.
