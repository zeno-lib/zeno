## Configure Drizzle Kit

Create a
[`drizzle.config.ts`](https://orm.drizzle.team/docs/drizzle-config-file) next to
the package or app that owns the schema:

```typescript title="{project}-db/drizzle.config.ts"
import "dotenv/config"
import { defineDrizzleConfig } from "@zeno-lib/db/config"

export default defineDrizzleConfig()
```

Keep `import "dotenv/config"` here. Next.js loads `.env*` files for code running
inside the Next runtime, and Vercel provides environment variables during builds
and function execution, but Drizzle Kit runs this config as its own CLI process.
The import makes local `.env` values available before `defineDrizzleConfig()`
reads `process.env.DATABASE_URL`.

The preset:

- Reads schema from `./src/schema.ts`.
- Writes migrations to `./supabase/migrations`.
- Uses the `postgresql` dialect.
- Reads `DATABASE_URL`.
- Keeps Supabase's built-in roles marked as existing.

You can still pass Drizzle Kit overrides for package-specific credentials or
paths — for example, a separate migrations connection string:

```typescript title="{project}-db/drizzle.config.ts"
import "dotenv/config"
import { defineDrizzleConfig } from "@zeno-lib/db/config"

export default defineDrizzleConfig({
  dbCredentials: {
    url: process.env.MIGRATIONS_DATABASE_URL ?? "",
  },
})
```

## Generate migrations

Recommended package scripts:

```json title="{project}-db/package.json"
{
  "scripts": {
    "dev": "pnpm exec supabase start",
    "stop": "pnpm exec supabase stop",
    "reset": "pnpm exec supabase db reset && pnpm db:seed",
    "db:generate": "drizzle-kit generate",
    "db:migrate": "drizzle-kit migrate",
    "db:seed": "node src/seed.ts"
  }
}
```

What each script does:

- `dev` starts your local Supabase stack, including local Postgres.
- `stop` stops the local Supabase stack.
- `reset` rebuilds the local database from migration files, then runs your seed
  script.
- `db:generate` reads your TypeScript schema and writes a SQL migration under
  `supabase/migrations`.
- `db:migrate` applies generated migrations to a database and records them in
  Drizzle Kit's migration table.
- `db:seed` runs your project-owned seed script.

Author tables and RLS policies in your Drizzle schema, run
`drizzle-kit generate`, review the generated SQL, and commit the generated SQL
under `supabase/migrations`. Apply generated migrations with
`drizzle-kit migrate` in environments where the database is not reset from
scratch.

## Pitfalls

- Do not remove `entities.roles.provider: "supabase"` from Drizzle Kit config,
  or generated migrations may try to create or drop Supabase-managed roles.
