## 0.4.1

### Patch Changes

- 4d9b339: `serverOwned` is now `serverManaged`, and `databaseManaged` marks a column only the database writes. A `serverManaged` column leaves the client `insert` and `update`, and `defineServerTableSchema` keeps it for the server code that sets it, as before. A `databaseManaged` column, one a trigger, a default or a database function sets, leaves both, so no input, server-side ones included, accepts a value the database would overwrite. The audit columns of `timestamps()` and `authorship()` already carry it. A column a trigger and server code both write stays `serverManaged`. Neither changes the DDL.
  
  Rename every `serverOwned(` to `serverManaged(`, then move the columns only the database writes to `databaseManaged(`.

## 0.4.0

### Minor Changes

- f85c80e: Column rules. `serverOwned(builder)` and `withRule(builder, refinement)` from `@zeno-lib/db/schema` mark a column inside `table`, `unsecureTable` or `schema(...).table`, and `defineTableSchema` reads the marks: a server-owned column leaves `insert` and `update`, and a rule applies to both. A function refinement passed in the options runs on top of the rule; a Zod schema replaces it. `select` keeps every column, without the rules. The table functions change no DDL.
  
  **Breaking:** `defineTableSchema` now leaves identity columns, `generated by default` ones included, out of `insert` and `update`. A form or action that names a row extends its schema with `select.shape.id`, which keeps the positive check.
- 3742592: `insert` and `update` check the format of a string-mode `date` or `timestamp` column, where Drizzle's bridge only asked for a string. A date must be a calendar date (`2026-09-17`). A timestamp takes a calendar date and a time, ISO 8601 or the text Postgres returns (`2026-09-17 07:53:56.357127+00`); one with a time zone needs its offset, and one without refuses an offset, which Postgres would drop. Both take `infinity` and `-infinity`, and an array column's elements go unchecked. The messages are Zod's own, so its locale applies. `select` stays unchecked.
- e0df074: Field hints. `withRule(builder, refinement, hint)` takes a hint for the form field that edits the column, and `percentage()` and `year()` give one: `{ field: "percentage", scale }` and `{ field: "year" }`. `defineTableSchema` registers it on the schema the rule returns, in a registry of its own rather than `.meta()`, so `z.toJSONSchema` leaves it out. The kit's `PercentageField` and `YearField` read it from the form's schema, through its wrappers (`.optional()`, `.nullable()`, `.describe()`, `.catch()`, `z.preprocess`), and take `min` and `max` from the schema's own `.min()` and `.max()`, so a refinement that narrows them narrows the field too.
  
  A field bound to such a column needs no `scale`, `min` or `max`. A prop passed to the field wins, and so does one from `defaultProps`: remove `scale`, `min` and `max` from the app-wide `PercentageField` and `YearField` defaults, or they override every column. `PercentageField`'s `allowNegative` now defaults to whether `min` is below 0, and `YearField` takes a negative year when `min` is below 0.
  
  `getFieldHints(field, kind)` in `@zeno-lib/forms/lib/field-hints` reads the hints for a field of your own.
  
  Update `@zeno-lib/forms` first, then re-add the `create-form` item with the shadcn CLI, or carry the change into your own `percentage-field.tsx` and `year-field.tsx`.
- 63449a6: `ownedRows(schema, { parent })` from `@zeno-lib/schema` describes the rows of a table that belong to a parent and are edited as a list, such as an order's lines. Its `row` is what a form validates each row with: the `insert` columns without the parent's, plus the `id` of a stored row. `syncRows` from `@zeno-lib/db/query` takes it in place of the table, and checks that `parent` names exactly its parent columns.
  
  `defineTableSchema` and `defineServerTableSchema` now return the `table` they derive from, beside `insert`, `select` and `update`.
- f16e285: The audit helpers mark their own columns. `timestamps()`, `createdBy()` and `updatedBy()`, so also `authorship()` and `auditColumns()`, record that the database writes them, and `defineTableSchema` leaves them out of `insert` and `update` under any key.
  
  **Breaking:** `defineTableSchema` no longer recognises audit columns by name. A column named `createdAt`, `createdBy`, `updatedAt` or `updatedBy` that you declare yourself, with a default, is now writable. Build it with the helper, or wrap it in `serverOwned()`, to keep it out of writes.
  
  `authUserId({ defaultToCurrentUser: true })` declares an owner column: `DEFAULT auth.uid()`, marked server-owned so no client picks the owner. `serverOwned()` on an audit column is a type error, and throws.
- 271c9c7: `defineServerTableSchema(table, options?)` is `defineTableSchema` for code that runs only on the server, such as a sync job: its `insert` and `update` keep the columns `serverOwned()` keeps from clients. Identity and audit columns stay out, as the database writes them: an upsert keyed on the id extends the schema with `select.shape.id`. Never parse a client's payload with it.
- e96ab84: `writableColumns(exports)` lists, for every Zeno table among a module's exports, the columns `defineTableSchema`'s `insert` and `update` accept, keyed by table name. Snapshot it in one test, so a column that becomes writable shows up as a diff in review.
- 76d0f96: **Breaking:** `defineTableSchema` takes only a table from `table`, `unsecureTable` or `schema(...).table` in `@zeno-lib/db/schema`. A plain drizzle `pgTable`, or a table from the re-exported `tableCreator`, is now a type error and throws at runtime, where its column markers used to be ignored without a trace. Derive a plain table's schemas with the re-exported `createInsertSchema`, `createSelectSchema` and `createUpdateSchema`.

## 0.2.2

### Patch Changes

- e0d7300: A function refinement on a nullable or defaulted column now keeps that field
  optional in the `insert` type. Drizzle typed it as required, while the parsed
  value could still omit it, so `defineTableSchema(t, { insert: { note: (s) =>
  s.min(1) } })` rejected payloads at compile time that it accepted at runtime.

## 0.2.1

### Patch Changes

- aca6029: The package now ships compiled `dist/index.mjs` and `dist/index.d.mts`, and
  `exports` points at them. It used to export `src/index.ts`, which bundlers that
  do not transpile `node_modules`, Next.js included, fail to load with "Unknown
  module type".

## 0.2.0

### Minor Changes

- b99ed9f: `defineTableSchema` now leaves the audit columns out of `insert` and `update`:
  `createdAt`, `updatedAt`, `createdBy` and `updatedBy`, when the column has a
  default, which is what `auditColumns()`, `timestamps()` and `authorship()` from
  `@zeno-lib/db/schema` emit. A caller who sends them has them stripped rather
  than written, and the inferred types drop them too. `select` still has them.
  
  Identity columns that count up from 1, including every `sequentialPrimaryId()`,
  now only accept positive numbers in all three variants.
  
  Breaking: an `.omit({ createdAt: true, ... })` on a derived `insert` or
  `update` schema now fails, because the key is already gone. Delete those keys
  from the omit.
